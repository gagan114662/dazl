# Dazl repository rules

These rules apply to changes anywhere in this repository. Read `docs/NEVER-AGAIN.md` and the repository release and review instructions before changing or deploying code.

**The goal (owner, 2026-11-22):** ship dazl as a production-ready, multi-tenant product that returns better leads than Gojiberry, and win its first paying customer. Progress is measured by [`BENCHMARK.md`](BENCHMARK.md), not by merged pull requests or closed issues. Where an older document disagrees with this file, this file wins.

- Do not hardcode places, industries, or company or person names in production targeting, discovery, or verification. Use the user's reviewed intent and independently sourced evidence. Keep test cases and recorded fixtures out of production paths.
- Claude is the only paid API allowed. The per-scan ceiling is USD 5; a lower trial, account, or platform limit still applies. Reserve before dispatch, account for all paid calls including search, fetch, and judging, and settle actual usage before authorizing more. An unknown charge or a refusal stops further paid work. Never describe an estimate as an invoice guarantee.
- Show leads; label what is missing. A lead is shown when it has a real company and a signal whose proof page names that company. A missing date, person, website or email lowers the lead's confidence and is said on the card; it never hides the lead. Only a lead whose proof nobody could confirm goes to review. Never invent a company, person, date, quote or link. The stricter checks still decide what automatic outreach may send.
- A fix never names a company, place, industry or job title. If a fix only makes sense for one case, change Claude's instructions or the lead record instead.
- The benchmark decides. Every pull request that touches lead finding or what is shown posts the benchmark table before and after (`bench/README.md`), run on real search and real model calls on staging, at no more than US$1 per prompt. A change that lowers leads shown, dated proof or named people does not merge. Launch-safety work (backups, alerts, isolation, deploys) is exempt. Missing or unknown results are not a pass.
- No test-only shortcuts, bypasses, fake readiness, replay flags, or special-case credentials in production paths. Never log private evaluation briefs, tokens, raw provider output, or tenant data in shared CI artifacts.
- Lead finding is one Claude loop (`web/lib/discover`), on by default for an ordinary request. Job boards, registries and crawls only add detail to a lead; they never decide whether it is kept. Remove older finding paths as the loop replaces them; do not add a second engine.
- An issue is closed only when its change is live and checked on the real product, with the proof in the issue. An issue whose deliverable is not part of the deployed product (a benchmark, a report, repository tooling) is labelled `no-deploy` and closes on a `Repo check (commit <sha>): PASS` comment with the evidence. Do not close issues in bulk, and do not open a new issue for work that fits an open one.
